## Resumen

Ciclo enfocado en diagnosticar y reparar la compilación de `opencode-vMK.exe` que
fallaba por el uso de dynamic `import()` en la función `lazy()` — Bun.compile()
no empaqueta módulos solo alcanzables por dynamic import.

## Hallazgos

### 1. Build roto por lazy dynamic imports
- **Severidad**: 🔴 Crítico (binario no arrancaba)
- **Causa raíz**: Commit `84c678477` reemplazó 23 static imports con `lazy()` usando
  `await import(path)` dinámico. Bun.compile() no incluye módulos sin una cadena
  de import estática.
- **Error**: `Cannot find module './cli/cmd/tui' from 'B/~BUN/root/src/index.js'`
- **Fix**: Static registry `_registry.ts` con los 23 imports + `lazy()` lo consulta
  primero (`cmdRegistry[path] ?? await import(path)`)

### 2. vmk.cmd ANSI VT hack roto
- **Severidad**: 🟡 Medio (cosmético, rompía la salida)
- **Causa raíz**: `DllImport("kernel32.dll")` sin quoting correcto en C# embedded
- **Fix**: Eliminado el hack — el binario y `@opentui/core` manejan VT processing internamente

## Aprendizajes

- Bun.compile() solo empaqueta módulos alcanzables vía static imports desde entrypoints
- Dynamic `import()` con string literal NO es suficiente para Bun.compile — necesita
  cadena de import estática o entrypoint explícito
- El `lazy()` original con dynamic import fue una optimización válida para dev mode
  pero incompatible con compile. El registry con fallback resuelve ambos modos.
- `vmk.cmd` usa `%~dp0` para paths relativos → siempre seguro, sin injection
